# Build 1 audit — 2026-07-28

_33 CONFIRMED of 38 adversarially-verified findings, 6 dimensions._

## Verdict
No — do not tag Build 1 or cut an exe yet. The eight binding constraints from docs/TABS_BUILD_PLAN.md §1 all held (no confirmed violation of the [hidden] rule, .collapsed inspector, toast layout, PHI-free export filename, kill-switch/sandbox gating, enter-only animations, reduced-motion, or the src/render//src/sources freeze), but the build misses its own §2b and §3a acceptance criteria: one blocking pdf.js lifecycle leak on the most common multi-tab path, a wrong-claim-export state after a failed render, a duplicate-tab/shared-session bug that hard-breaks a restored tab, and a role="tablist" that ships with no keyboard contract at all. All ten must-fix items are localized to src/renderer/{tabs,main,inspector,shortcuts}.ts plus two E2E files — this is one focused fix pass, not a rework. The two mandated verifications (§2 watch-out fake-counting lifecycle unit test, §3a a11y spec) were never built, and they are the direct reason the top two defects shipped; land those with the fixes, re-run the gate, then tag.

## MUST FIX (10)

1. BLOCKING — background-tab pdf release is bypassed on every open-into-a-background-tab. src/renderer/tabs.ts:200-201 has createTab set state.activeTabId itself, so by the time src/renderer/main.ts:609 calls activateTabById, previousTab === the new tab, switchingAway is false, and neither cancelInFlightRender (main.ts:430) nor setActivePdfDoc(previousTab, null) (main.ts:436-438) runs. Opening N files leaves N live PDFDocumentProxy/worker documents. Fix: make activateTabById the ONLY writer of state.activeTabId — add an `activate` option to createTab (default false on the performOpen path) or snapshot the outgoing tab before creating. (The rapid-Ctrl+Tab variant is NOT affected — do not carry that rationale into the fix.)

2. MAJOR — a failed claim:getPdf leaves the tab describing one claim while the canvas shows another, and export follows the wrong one. src/renderer/main.ts:320-322 writes tab.currentIndex before the awaits; if getPdf (main.ts:341) rejects, setActivePdfDoc (main.ts:343) never runs, the OLD document stays painted, and stepClaim's catch (main.ts:404-406) only toasts. The state sticks because ensureClaimRendered sees tab.pdfDoc truthy (main.ts:339). openExportDialog/confirmExport then read tab.currentIndex (src/renderer/overlays.ts:193-195, 218) and can export a different claim than the one on screen. Reachable: claim:getPdf runs renderClaim() in main (electron/main.ts:688-690) and can throw per-claim while claim:getDetail succeeds. Fix: assign currentIndex/detail together only after getDetail resolves; on catch, roll back or setActivePdfDoc(tab, null) to force a rebuild; disable export in the failed-step state.

3. MAJOR — same-file dedupe misses lazily-restored 'unloaded' tabs, producing a duplicate tab whose two TabStates share ONE main-process sessionId; closing either kills the other. performOpen's only dedupe is by sessionId (src/renderer/main.ts:590), restored tabs carry sessionId=null (main.ts:750 -> src/renderer/tabs.ts:185), so re-opening an unloaded tab's file mints a fresh session and a second tab; activating the original then hits main's path dedupe (electron/main.ts:577-593) and hands it the SAME sessionId. closeTab calls closeSession unconditionally (tabs.ts:217-219) and electron/main.ts:757 does a refcount-free sessions.delete, so the survivor's next getPdf/getDetail throws 'No claim file is open.' (electron/main.ts:836-837) — guaranteed, because background release forces a reload. Violates §2b (docs/TABS_BUILD_PLAN.md:167) and is faithfully re-persisted every launch. Fix: dedupe by resolved filePath in performOpen (the comparison reopenLastClosedTab already uses at main.ts:644); defensively dedupe validTabs by filePath in session:getRestoreState (electron/main.ts:794).

4. MAJOR — every tab's close button is a full Tab stop, defeating the strip's roving tabindex. src/renderer/tabs.ts:281-288 creates the close <button> with no tabIndex (native 0) nested inside the role="tab" div, while tabs.ts:267 does the roving `el.tabIndex = isActive ? 0 : -1` on the .tab divs only; style.css:668-672 keeps the button rendered at all times. Contradicts inspector.ts:173's explicit copyBtn.tabIndex = -1 and violates docs/TABS_BUILD_PLAN.md:317-318 ('only one tab in the tab order'). Fix: set close.tabIndex = -1 and add a Delete/Backspace close path in the strip keydown handler.

5. MAJOR — the role="tablist" strip has no keyboard handler at all. src/renderer/index.html:80 declares role=tablist and tabs.ts:263-267 stamps role=tab/aria-selected/roving tabindex, but initTabStrip (src/renderer/tabs.ts:303-332) registers only 'click' and 'auxclick'; no keydown listener on tabStripEl exists anywhere. Since .tab is a <div>, Enter/Space do nothing and Arrow/Home/End do not move the roving index — a focused tab is a dead end. docs/TABS_BUILD_PLAN.md:315-321 requires Left/Right/Home/End for this build. Fix: delegated keydown in initTabStrip modeled on inspector.ts:208-240 (Arrows/Home/End move + activate, Enter/Space activate, Delete closes).

6. MAJOR — renderTabStrip() wipes the strip with innerHTML='' (src/renderer/tabs.ts:258) and nothing ever restores focus, so closing or switching a tab — and every claim step, since ensureClaimRendered re-renders at main.ts:351 — drops focus to <body>. Neither closeTab (tabs.ts:211-234) nor closeTabById (src/renderer/main.ts:483-500) reads or reassigns document.activeElement, and no call site focuses afterwards. Unmet docs/TABS_BUILD_PLAN.md:319-320. Fix: capture whether focus was inside tabStripEl and re-focus the newly-active .tab (or #welcomeOpenBtn on last close), or reconcile strip nodes instead of wiping.

7. MAJOR — Ctrl+Shift+C double-fires when focus is on an inspector row: two clipboard writes and two toasts. src/renderer/inspector.ts:213-214 matches `ctrlOrCmd && key.toLowerCase() === 'c'` with no !event.shiftKey, and the branch (215-219) preventDefaults but never stopPropagation, so the event bubbles from inspectorBodyEl (inspector.ts:208) to the window dispatcher (src/renderer/shortcuts.ts:182-186 -> main.ts:931-935). Final clipboard contents are ordering-dependent. e2e/copy.spec.ts:84-99 misses it because the chord is pressed with focus on a <summary>-hosted button, where closest('.inspRow') is null. Fix: add `&& !event.shiftKey` at inspector.ts:214 and stopPropagation() in that branch.

8. MAJOR — F1 and Ctrl+E stack a second modal overlay, breaking Escape ordering and focus restore. src/renderer/shortcuts.ts:124-128 handles F1 before any overlay check and shortcuts.ts:194-196 opens the export dialog with no anyOverlayOpen() guard, unlike its neighbours (overlays.ts:238, main.ts:393/503/510/520). openOverlay (src/renderer/overlays.ts:106-128) neither closes an open overlay nor keys lastFocusedBeforeOverlay (a single module global at overlays.ts:63, overwritten at :117). Export-then-F1 leaves both non-hidden; Escape resolves to 'export' by fixed OVERLAY_IDS order (overlays.ts:84, 156-158), overlays.ts:140 focuses a display:none dialog, focus falls to <body>, and the shortcuts sheet's Tab trap stays live. Fix: guard both entry points with anyOverlayOpen() (or have openOverlay close the current one first) and key lastFocusedBeforeOverlay by OverlayId like overlayCloseTimers at overlays.ts:85.

9. MAJOR (test integrity) — e2e/tabs.spec.ts:12-13 claims coverage for same-file dedupe, middle-click close and Ctrl+W, but the file has only two tests (:81, :154) and neither uses a keyboard or a middle button; a repo-wide grep of e2e/ finds no `{ button: 'middle' }` and no Ctrl+W/Ctrl+Tab/Ctrl+1-7 press. All four are shipped deliverables of 735834e (shortcuts.ts:151-155, 203-206, 243-251; tabs.ts:318-322). Fix: add the four interaction tests (Ctrl+W closes the tab and leaves app.windows().length === 1; Ctrl+Tab cycles; Ctrl+1/2 jump; middle-click closes) or, at minimum, correct the header so it stops asserting coverage that does not exist. (The 'Ctrl+W closes the window' risk is largely neutralized by Menu.setApplicationMenu(null) at electron/main.ts:942.)

10. MAJOR (test integrity) — every per-tab render assertion checks only that the shared canvas has non-zero width/height (e2e/tabs.spec.ts:115-117, 128-130; session-restore.spec.ts:113-115; app.spec.ts:236; multi-form.spec.ts:107,114,138), and no test in the repo reads a pixel (no toDataURL/getImageData anywhere). A cross-tab or stale render passes every assertion, because the surrounding chrome checks are painted from the tab's cached detail, not the canvas — so the tab-stamped render serialization added in 735834e (src/renderer/preview.ts:18-19, 53) has no regression test. Fix: fingerprint the canvas per tab and assert it changes/matches across switches; add an un-awaited A->B->A switch test; assert getDetail/getPdf on a closed sessionId rejects.

## SHOULD FIX (13)

1. Per-tab zoom/zoomMode/pageNum are discarded on every re-focus: the lazy rebuild path treats `!tab.pdfDoc` as 'claim changed', hard-resets tab.pageNum = 1 (src/renderer/main.ts:339-346) and calls fitPage(tab, true) (main.ts:354-355 -> src/renderer/preview.ts:178-183). Currently self-masked by the blocking bug, so it becomes MORE visible once that is fixed — do both together. Fix: reset pageNum only on opts.forceReload; after a lazy rebuild clamp pageNum to doc.numPages and dispatch on tab.zoomMode.

2. Closing a tab mid-load orphans a live pdf.js document/worker forever. closeTab splices the tab then calls setActivePdfDoc(tab, null) while tab.pdfDoc is still null — a no-op (src/renderer/tabs.ts:211-226, 138-151) — and the resumed ensureClaimRendered assigns the fresh proxy to a detached TabState (src/renderer/main.ts:341-343); the only liveness guard is one line too late at main.ts:352, so loadingTask.destroy() (tabs.ts:144) can never run. Fix: re-check `findTabById(tab.tabId)` / state.tabs.includes(tab) after each await and destroy the just-created doc, or add a `closed` flag that makes setActivePdfDoc destroy an incoming doc.

3. Switching tabs mid-load falsely marks the outgoing tab status 'error' and flashes the error screen. Destroying the transport rejects the in-flight getPage (verified against node_modules/pdfjs-dist/build/pdf.mjs:16251-16255, 16580-16595), and pageBaseSize awaits getPage with no catch (src/renderer/preview.ts:45-50); the rejection propagates into activateTabById's catch (main.ts:448-452). A post-await guard does NOT fix this — the await rejects, so the rejection must be CLASSIFIED as a cancellation and swallowed. Also attach a .catch() to the wheel handler's `void applyZoom(...)` (preview.ts:265-274), which currently has no rejection handler.

4. Windows case-insensitive dedupe gap: electron/main.ts:577-579 resolve()s but never case-folds, and inFlightOpensByPath (:554, :595, :629-633) inherits the same key, so two differently-cased spellings of one file open two sessions and two tabs holding two copies of the same PHI. Reachable via a path typed/pasted into the Open dialog's filename box or a hand-edited session.json. Fix: fold the key on win32 for both the sessions scan and the in-flight map while still storing/returning the original-cased resolved path.

5. Extension allow-list is enforced asymmetrically: the dialog path offers an 'All files' filter and never checks (electron/main.ts:672-685 -> :576-635), but isRestorableFileRef gates both tabs and recentFiles on the way back (:153-155, :794, :801) — so a .x12/.837p/extensionless 837 opens and renders, is recorded (:619, consuming a recents slot), then silently vanishes on next launch and cannot be reopened from recents. Fix: make one gate authoritative; note that relaxing isRestorableFileRef alone is insufficient because the restore-activation call re-enters via the droppedPath branch (electron/preload.ts:130 -> electron/main.ts:647) and re-applies the check.

6. session:save accepts an unbounded renderer-supplied array — no cap on entry count or path-string length in the handler (electron/main.ts:813-823) or the store, while recentFiles IS capped one line away (src/app/persistence/sessionStore.ts:64 vs :65). Cost is a large startup cost (one tab per stored ref at src/renderer/main.ts:750) and a full read-modify-write per tab event. Fix: slice `validated` to a ceiling (e.g. 64) and reject over-long paths in the handler, and mirror the cap in sanitize() so a hand-edited session.json can't reintroduce it.

7. No permission handler on the default session — setPermissionRequestHandler/setPermissionCheckHandler/setDevicePermissionHandler appear nowhere in electron/, src/ or scripts/; whenReady (electron/main.ts:934-945) installs only the kill-switch, null menu, IPC and window. Ordinary hardening, not a Build 1 regression and not a binding-constraint 5 issue (clipboard use predates Build 1: build-0-preflight-green src/renderer/main.ts:1446). Fix: deny by default next to installOfflineKillSwitch, but explicitly ALLOW 'clipboard-sanitized-write' or the whole copy suite (src/renderer/clipboard.ts:24-29) degrades to the failure toast; verify against the clipboard E2E.

8. Collapsed inspector keeps ~8 newly-added focusable rows Tab-reachable inside a width:0/opacity:0 drawer: #inspector.collapsed (src/renderer/style.css:1212-1218) deliberately avoids `hidden`/visibility/inert (correct per guardrail 2), but Build 1 added `firstRowEl.tabIndex = 0` per group (src/renderer/inspector.ts:186) plus always-focusable group copy buttons (:243-249), and only F6 skips the collapsed region (main.ts:996-1004). Fix: toggle `inert` on #inspectorHeader/#inspectorBody in updateInspectorVisibility (inspector.ts:55-66), or drop roving rows to -1 while collapsed.

9. Focus restore after a menu-invoked dialog targets a display:none menu item, so focus lands on <body>. closeAllMenus hides the panel (src/renderer/main.ts:809-816) before runAction opens the overlay (:848-906) and openOverlay captures document.activeElement (src/renderer/overlays.ts:117), making overlays.ts:140's restore a no-op. Affects export, shortcuts and both Build 1 additions (about, forget). Unmet docs/TABS_BUILD_PLAN.md:322. Fix: focus the owning .menuTrigger before opening, or have openOverlay reject a capture candidate with no layout box.

10. PageUp/PageDown are preventDefault'd unconditionally at window level (src/renderer/shortcuts.ts:144-153), so the now-Tab-reachable #inspectorBody (a real overflow:auto scroller, style.css:1236-1239) cannot be paged — it steps the claim instead. 11. Unserialized read-modify-write on session.json: saveOpenTabs and addRecentFile both do loadSession -> spread -> writeSessionAtomic with an await in between and no lock (src/app/persistence/sessionStore.ts:109-121). The realistic window is the already-open dedupe branch's un-awaited `void recordRecentFile` (electron/main.ts:584) — worst case a lost recent-files reorder, not a lost tab — plus overlapping saves from `void activateTabById` on rapid Ctrl+Tab (src/renderer/main.ts:511, 517) persisting a stale activeIndex. Fix: serialize store mutations behind a module-level promise chain; add a Promise.all unit test.
